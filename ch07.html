第7章

config.ocio をさわる

OCIO の実体は、ただの文字が書かれた1つのファイルです。開いて、書きかえて、絵が変わるところまでやってみます。

中身はこれだけです

こわがる必要はありません。いちばん小さい config.ocio の全文がこれです。

ocio_profile_version: 2

name: minimal
description: 学習用の、いちばん小さい設定

# --- ロール: どの色空間を何に使うかの割りあて ---
roles:
  reference: linear
  scene_linear: linear
  data: raw
  default: srgb_display
  color_picking: srgb_display

# --- 色空間: この設定で扱う色空間の一覧 ---
colorspaces:
  - !<ColorSpace>
    name: linear
    family: 基本
    description: 光の量そのもの。作業はここで行う
    encoding: scene-linear
    isdata: false

  - !<ColorSpace>
    name: srgb_display
    family: 出力
    description: パソコンやスマホの画面用
    encoding: sdr-video
    isdata: false
    from_reference: !<BuiltinTransform> {style: "LEARNING - ACES_OUTPUT_SDR100"}

  - !<ColorSpace>
    name: raw
    family: 基本
    description: いっさい変換しない
    isdata: true

# --- 画面と見せかた ---
displays:
  sRGB:
    - !<View> {name: 標準, colorspace: srgb_display}
    - !<View> {name: そのまま, colorspace: raw}

覚えるのは5つだけ

書くところ意味
rolesどの色空間を何に使うかの割りあて。ソフトはこの名前で色空間を探します
colorspacesこの設定で扱う色空間の一覧
displaysどの画面に出すか
viewsその画面での見せかた。displays の中に書きます
looks味付け。View から名前で呼び出します

行ごとの意味

  • roles: のところ。scene_linear: linear は「光の量そのものを扱うときは linear という色空間を使う」という意味です。ソフトは色空間の名前を直接知らなくても、この役割の名前で探せます。
  • - !<ColorSpace> で始まるかたまりが、色空間1つぶんです。
  • from_reference: は「基準の色空間から、この色空間へ行く変換」です。逆向きは to_reference: です。
  • isdata: true は「これは色ではなくデータなので、いっさい変換しない」という印です。
  • displays: の下の sRGB: が画面の名前、その下の - !<View> が見せかたです。

自分で書きかえてみる

下のエディタで実際に書きかえられます。左を直すと右の絵がすぐ変わります。課題が4つあります。上から順にやってみてください。

こわしてください

わざと変な設定にして、どんなエラーが出るか見るのがいちばん勉強になります。リセットを押せば、いつでも元にもどせます。

ここは動かして見る部分です

JavaScript を有効にすると、config.ocio を書きかえて結果をその場で見られる練習ができます。課題は4つあります。色空間を足す、こわれたロールを直す、味付けを足す、出力先を切りかえる、です。

課題2で何が起きているか

課題2の設定は、scene_linear というロールが、画面用の色空間を指しています。これは「光の量そのもの」を指す約束の場所なので、まちがいです。

ここがずれていると、第5章で見た計算がすべて狂います。ぼかしても合成しても、光の量ではない数字を混ぜることになるからです。たった1行のまちがいで、作品全体がおかしくなります。

現場ではどう使うか

実際の作業では、パソコンの 環境変数 OCIO に、この config.ocio の場所を設定します。

# Mac や Linux の場合
export OCIO=/Users/あなた/projects/myshow/config.ocio

こうしておくと、OCIO に対応したソフトが起動時にこのファイルを読み、全部が同じ変換を使うようになります。チーム全員が同じファイルを共有すれば、全員の画面で同じ色になります。

自分でゼロから書く必要もありません。ACES 用の config は公式に配布されていて、CG 向けの軽いものと、映画制作向けの大きなものがあります。ふつうはそれを使います。

このエディタについて

このサイトのエディタは学習用の簡略版です。本物の OpenColorIO の機能のうち、話に必要な部分だけを再現しています。対応していない書きかたは、黙って無視せずエラーとして表示します。

ここで書いた設定は、LEARNING - で始まる行を除けば、本物の OpenColorIO でも読める形です。

この章のまとめ

  • config.ocio は、変換のルールを書いた1つのテキストファイル。
  • 覚えるのは roles, colorspaces, displays, views, looks の5つ。
  • roles は「役割の名前」で色空間を探すしくみ。ここがずれると計算が全部狂う。
  • 環境変数 OCIO でファイルの場所を教えると、対応ソフトがそろって同じ設定を使う。
