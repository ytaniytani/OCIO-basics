第3章

明るさの数字は正直じゃない

色空間の3つめの約束、伝達関数の話です。ここが分かると、第5章の「なぜ計算が壊れるのか」に一気につながります。

50%グレーは、本当に半分?

画像ソフトで「50%のグレー」を作ります。数値でいうと 8bit の 128 くらいです。

8bit というのは、明るさを真っ黒 0 から真っ白 255 までの 256段階で表すやりかたのことです。だから 128 はちょうどまん中の段階になります。同じ明るさを 0.0〜1.0 で書くこともあり、その場合は 0.5 です。

このグレーは、白の半分の明るさでしょうか。まずは自分で予想してから、下の問題に答えてみてください。

ここは動かして見る部分です

JavaScript を有効にすると、2問のクイズで確かめられます。答えを先に書いておくと、光を半分にしたときの 8bit の値は 128 ではなく 188 です。逆に 8bit の 128 は、光の量にすると 21.6% しかありません。

答えは 21.6% でした。半分どころか、5分の1くらいしかありません。

わざと曲げてあります

光の量と数値が正直に対応していたら、光を半分にすれば数値も半分になるはずです。まっすぐな比例の関係、ということです。でもさっきのクイズどおり、光を半分にしても数値は 188 までしか下がりませんでした。

光の量と数値の関係は、まっすぐな比例ではなく、途中で折れ曲がっています。暗い光にはたくさんの数値を、明るい光には少しの数値を割りあてる、という曲がりかたです。このサイトでは、この関係を「曲げる」と呼びます。どんな形に曲がっているかは、あとの「さわる」でグラフに描いて見せます。

これはバグではありません。わざとそうしてあります。理由は2つです。

理由1: 人の目は暗いところに敏感だから

人の目は、暗いところのわずかなちがいはよく見分けられますが、明るいところのちがいにはにぶくなっています。だから数値の段階は、暗い側に多く割りあてたほうが得です。

理由2: 8bit は256段階しかないから

ふつうの画像は1つの色あたり256段階しか持てません。もし光の量をそのまま素直に記録すると、暗い部分に使える段階が足りなくなり、空のグラデーションなどに縞(しま)が出ます。

そこで、暗い側をひきのばして段階を多く配り、明るい側は詰める、という曲げかたをします。この曲げかたのルールが 伝達関数 です。ガンマ という言葉も、ほぼ同じ意味で使われます。

曲がりかたを目で見る

横が光の量、縦が保存される数値です。線の上をなぞると、対応する2つの値が読めます。曲げかたを切りかえて、形のちがいを見てください。

グラフには 「中間グレー 0.18」 という印が出ます。ここはこのサイトでいちばん誤解されやすいところなので、先にじっくり説明します。

「中間グレー」「18%グレー」とは何のことか

まず、「中間グレー」はこのサイトだけの言葉ではありません。写真・映像・CG のどの現場でも使う、ふつうの言葉です。英語では middle grey、日本語では「18%グレー」とも言います。

指しているのは、当たった光のうち 18% を返す灰色です。この「何%を返すか」を 反射率 と言います。カメラ用品の店には、そのとおりに作った「グレーカード」という板が売っています。撮影のときに画面へ入れて、明るさの基準にするための道具です。

「じゃあ白は 100% 反射するの?」— いいえ

ここでほとんどの人がひっかかります。「18% を返す灰色」なら、白は 100% 返すのか。鏡でもないのに、そんなことある?という疑問です。

答えは「いいえ」です。2つの別の話が混ざっています。

  1. 反射率 — ものの性質。当たった光のうち何%を返すか。
  2. 光の量の目もり — 数字のふりかた。どこを 1.0 と呼ぶか。

反射率が 100% のものは、実際にはありません。白い紙でも 80〜90% くらいです。残りは紙に吸われて熱になります。真っ黒なビロードだと 1% くらいまで落ちます。

では 1.0 は何かというと、「当たった光をぜんぶ返す理想の白」を 1.0 と呼ぶことにした、という決めごとです。実在の品物ではなく、目もりを決めるためだけの基準点です。このサイトではこれを 基準の白 と呼びます。

だから、実物の白い紙は 1.0 に少し届きません。0.85 くらいです。18%グレーカードは 0.18 ちょうどです。

反射するものを並べると、こうなります。いちばん右は、その光の量を sRGB で保存したときの見た目です。

もの反射率光の量8bit見た目
基準の白(当たった光をぜんぶ返す理想の白)100%1.00255
白い紙80〜90%0.85237
白と黒の市松模様を遠くから見たとき約47%0.47182
18%グレーカード(中間グレー)18%0.18118
黒い紙、黒い服3〜5%0.0456
黒いビロード1%くらい0.0125

見た目の列を上から見てください。18% の行が、いちばん「まん中の灰色」らしく見えるはずです。約47%の行は、もうかなり明るい灰色です。これがこの章の話そのものです。光の量と、人が感じる明るさは比例していません。

大事: 1.0 は上限ではありません

ここまでは反射の話でした。反射しているものは 1.0 を超えられません。当たった以上の光を返すことはできないからです。

でも世の中には、反射ではなく自分で光っているものがあります。

  • 電球、スマホやテレビの画面
  • 空、雲
  • 水面や金属のギラッとしたところ(鏡面反射)
  • 太陽

これらは平気で 1.0 を何倍も、何百倍も超えます。第1章の表に「1.0 を超えることがふつうにある」と書いたのは、このことです。第4章の白飛びも、第10章の HDR も、ぜんぶこの「1.0 の上」の話から始まります。

まぎらわしい: 0〜1 の目もりは2つ出てきます

このあとのグラフは、横も縦も 0〜1 です。でも意味がちがいます。

  • 横 = 光の量。0.0 が真っ暗、1.0 が基準の白。1.0 を超えることがある。
  • 縦 = 保存される数値。0.0 が真っ黒、1.0 が真っ白。8bit の 0〜255 と同じもの。

中間グレーの 0.18 は、横(光の量)のほうです。0〜255 のうちの 0.18 ではありません。

「中間グレー」と聞いて、こう思いませんでしたか

思ったこと答え
人の目に、白と黒のちょうどまん中に見える灰色のこと? ほぼ合っています。18% の光を sRGB で保存すると数値 0.461、8bit で 118。0〜255 のまん中あたりです。人がまん中と感じる灰色は、光の量では半分ではなく5分の1くらいしかない ── これがこの章の主題です。
カメラが露出を合わせるときの基準? 合っています。グレーカードを写して明るさの基準にするのは、いまでもふつうのやりかたです。CG や映像の計算でも、この 0.18 を基準の明るさとして使います。第10章では「中間グレーを何 nit で出すか」という形でまた出てきます。
白と黒の市松模様を遠くから見たときの色? ちがいます。白(90%)と黒(4%)が半分ずつ返すので、平均すると約 47%。上の表の3行目です。18% の2倍以上あり、中間グレーよりずっと明るい灰色になります。
もっとくわしく: なぜ 50% でも 20% でもなく 18% なのか

18% という数字の説明のしかたはいくつかあります。よく使われるのは、白と黒の「かけ算のまん中」だ、という見かたです。

白い紙が 90%、真っ黒に近いものが 3.6% を返すとします。この2つのかけ算のまん中(かけて平方根をとった値)を計算すると、ちょうど 0.18 になります。

0.90 × 0.036 = 0.0324
√0.0324 = 0.18

ふつうの「たし算のまん中」なら (0.90 + 0.036) ÷ 2 = 0.468 で、約47%です。でも人の目の感じかたは、たし算ではなくかけ算(何倍か)に近いのでした。だから「まん中の灰色」も、かけ算のまん中で考えたほうが実感に合います。

なお、実際の撮影ではカメラの露出計のくせもあって、 18% ぴったりで運用しない現場もあります。それでも「中間グレー = 光の量 0.18」は、CG と映像の計算では共通の約束として使われています。このサイトでもずっと 0.18 で通します。

ここは動かして見る部分です

JavaScript を有効にすると、sRGB、Rec.709、ガンマ2.2、ACEScct、Log などの曲線を切りかえて比べられます。点線がリニア(曲げない場合)です。sRGB の線はそれより上にふくらんでいて、暗い光にも大きめの数値を割りあてていることが分かります。

見どころが3つあります。

  • 点線(リニア)より上にふくらんでいる。 暗い光にも大きめの数値を割りあてている、という意味です。
  • 中間グレー 0.18 の印。 曲げかたを切りかえても、横(光の量)は 0.18 のまま動きません。動くのは縦(保存される数値)のほうだけです。
  • ACEScct と Log は、1.0 を超える光も収まる。 Log(ログ)は、とても広い明るさを 0〜1 の中に詰めこむ記録のしかたです。ACEScct(エーシーイーエス・シーシーティー)は、その考えかたを色の調整用に整えたものです。どちらも第8章と第9章でまた出てきます。横軸の目もりを 1、10、100 と「何倍か」で刻むやりかたを対数と言います。「横軸を対数にする」を押すとその目もりに変わり、Log の線がまっすぐになります。

計算するときは、曲げをほどく

曲げてあること自体は問題ありません。問題は、曲がったままの数値で計算してしまうことです。

足し算も平均も、光の量に対してやらないと正しい答えになりません。だから計算の前に曲げをほどいて光の量にもどし、計算が終わってから、見るためにまた曲げます。

この「ほどく」「曲げる」を、素材ごとに正しくやってくれるのが OCIO です。曲がったまま計算すると具体的に何が起きるのかは、第5章で実際に見ます。

この章のまとめ

  • 画面用の数値は、わざと曲げてある。暗い側に段階を多く割りあてるため。
  • 8bit(0〜255の256段階)の 128 は、光の量では 21.6% しかない。
  • 光の量を半分にしても、8bit の値は 188 までしか下がらない。
  • 計算するときは、いったん曲げをほどいて光の量にもどす。
