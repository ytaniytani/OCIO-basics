第8章

ACES というみんなのルール

OCIO は「変換のしくみ」を用意してくれます。では、どの色空間を共通の場にするか。その答えを業界が用意したものが ACES です。

共通の場所を、誰が決めるのか

第6章で、素材を「共通の作業空間」にそろえました。ではその共通の場所は、どこにすればいいのでしょう。

自分たちで決めることもできます。でも作品ごと、チームごとにバラバラだと、こんどはチームとチームの間で同じ問題が起きます。他の会社に映像を渡したとき、また色が合わなくなります。

世界共通の方眼紙

ACES(エーシーズ)は、映画業界が作った共通ルールです。正式には Academy Color Encoding System と言います。「どの色空間を共通の場にするか」を、世界中で1つに決めてしまおう、という考えかたです。

ACES を1文で言うと

どんな素材も、いったん世界共通の広い方眼紙に写す。そこで作業して、最後に出力先ごとに刷り上げる。

ACES のやりかたは、4つの段でできています。

段よび名やること
1入力変換(Input Transform / IDT)どのカメラの絵も、ACES の座標に翻訳する
2作業空間合成や CG の足しこみをする
3ルック(LMT)作品ぜんたいの味付けをする
4出力変換(Output Transform)見る機械に合わせて仕上げる

作業空間が3つあるのはなぜ?

ACES には作業空間が3つあります。多すぎると思うかもしれませんが、それぞれ用途がちがいます。

名前使いみちなぜそれが必要か
ACES2065-1(AP0)保存と受けわたしいちばん広い。将来どんなカメラや画面が出てきても入るようにしてある
ACEScg(AP1)CG と合成の作業リニアで、計算しやすい広さ。CG の光の計算に向く
ACEScct色の調整対数なので、調整つまみの効きかたが自然になる

第2章の色度図で ACES2065-1 を表示すると、三角形が馬蹄形からはみ出していました。人の目に見えない色まで含んでいるということです。わざとそうしてあります。入れものを大きくしておけば、あとから何が来ても困らないからです。

流れを1枚で見る

素材が完成品になるまでの5つの段です。段を選ぶと、その時点の絵が見られます。素材と出力先も切りかえられます。

ここは動かして見る部分です

JavaScript を有効にすると、素材 → 入力変換 → 作業空間 → ルック → 出力変換 という流れを、段ごとの絵で追えます。出力先を切りかえても、最後の段だけが差しかわることが確かめられます。

途中の段が変に見えても、こわれていません

入力変換のあとの絵は、そのまま画面に出すと白飛びして見えます。まだ画面用に仕上げていないからです。作業中の画面が眠く見えるのは、正常です。

いちばん大事なのは、出力先を切りかえても、①から④までが何も変わらないことです。変わるのは⑤の出力変換だけです。

出力変換のよび名について

本や記事によって、よび名がちがうことがあります。整理しておきます。

バージョン出力の段の作り
ACES 1.xRRT(共通の仕上げ)と ODT(機器ごとの調整)の2段
ACES 2.0この2つが1つの Output Transform にまとまった

このサイトでは、新しいよび名の「出力変換」で通しています。古い記事で RRT や ODT という言葉を見かけたら、「出力変換の中身のこと」だと思ってください。

ACES と OCIO の関係

まぎらわしいので、はっきり分けておきます。

正体役割
OCIOソフトウェアのしくみ変換を実行する道具。中身のルールは自分で決められる
ACES業界の取り決めそのルールの中身。共通の場所と、変換の定義

つまり OCIO は入れもの、ACES は中身です。ACES 用の config.ocio は公式に配布されていて、ふつうはそれをダウンロードして使います。自分でゼロから書く必要はありません。

この章のまとめ

  • ACES は「共通の場所をどこにするか」を業界で1つに決めた取り決め。
  • 入力変換 → 作業空間 → ルック → 出力変換 の4段。
  • 作業空間は用途で3つ。保存用は広く、CG 用は計算しやすく、調整用は操作しやすく。
  • 出力先を替えても、手前の段は何も変わらない。
  • OCIO は入れもの、ACES は中身。
まえconfig.ocio をさわる つぎグレーディングはどこに入れる
