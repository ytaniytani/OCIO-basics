第2章

数字だけでは色は決まらない

同じ「175」でも、cm なのか inch なのかで意味が変わります。色もまったく同じです。

送った写真の色が変わった

スマホで撮った写真を友だちに送ったら、「なんか色がうすくない?」と言われた。パソコンで開いたら、自分のスマホで見たときより地味に見えた。

こういうことは、実際によく起きます。ファイルは1バイトも壊れていません。それでも色が変わって見えます。

仕事でも同じことが起きます。納品したデータを先方が開いたら色がちがう、という事故です。原因を説明できないと、作り直しになります。

「いちばん濃い赤」は機械ごとにちがう

画像の中で、いちばん濃い赤は (255, 0, 0) と書かれています。でもこの数字は「その機械が出せる、いちばん濃い赤」という意味でしかありません。

そして「いちばん濃い赤」がどれくらい濃いかは、機械によってちがいます。安いモニターの赤と、新しいスマホの赤では、同じ (255, 0, 0) でも出てくる色がちがいます。

だから、数字だけでは色は決まりません。「どの赤を基準にした数字なのか」という約束が必要です。その約束が 色空間(カラースペース)です。

たとえるなら

「175」という数字に「cm」という単位を付けて初めて長さが決まるのと同じです。色の数字にも単位にあたるものが要ります。それが色空間です。そして画像ファイルには、その単位を書いたラベルが入っています。

色空間は3つの約束でできています

約束意味この章で見る?
① 原色(げんしょく)もとになる赤・緑・青をどこに置くか見ます
② 白色点(はくしょくてん)「白」をどの色にするか見ます
③ 伝達関数(でんたつかんすう)数値と明るさの関係をどう曲げるか第3章で

色の地図を見る

下の図は「色の地図」です。馬蹄形(ばていけい)の中が、人の目に見える色すべてです。その中の三角形が、それぞれの色空間で表せる範囲を表します。

ここは動かして見る部分です

JavaScript を有効にすると、色空間ごとの範囲を重ねて比べられます。sRGB がいちばん小さく、Rec.2020 はかなり大きく、ACES2065-1 は馬蹄形からはみ出すほど大きい、という関係です。

三角形が大きいほど、濃い色まで出せます。sRGB は小さく、Rec.2020 はかなり大きいことが分かります。

ラベルをまちがえると、こうなります

では、ラベルをわざとまちがえてみましょう。読みこんでいる数値は左右でまったく同じです。ちがうのは「どの色空間のつもりで開いたか」だけです。

ここは動かして見る部分です

JavaScript を有効にすると、色空間のラベルをまちがえたときに色がどう転ぶかを比べられます。広い色空間だと思って開くと色がうすくなり、リニアだと思って開くと白っぽくなります。

広い色空間だと思って開くと、色がうすく見えます。「もっと濃い赤も出せるはずだ」と思って、控えめに表示してしまうからです。

そして「二重変換」のスイッチも試してみてください。これはすでに変換ずみの画像に、もう一度同じ変換をかけてしまう事故です。誰がどこで変換したのかをチームで決めておかないと、実際に起こります。

数字とラベルは、いつもセット

直しかたは1つです。数字だけを渡さず、必ずラベルもいっしょに渡すこと。

そして受け取った側は、そのラベルどおりに解釈すること。これができていれば、どの機械で開いても同じ色になります。

ところが素材が10個も20個もあって、しかもソフトが何種類もあると、これを手作業でやるのは無理です。そこを自動でやってくれるのが OCIO です。第6章で登場します。

この章のまとめ

  • 数字だけでは色は決まらない。「どの色空間の数字か」という約束が要る。
  • 色空間は、原色・白色点・伝達関数の3つの約束でできている。
  • ラベルをまちがえると、数字は同じままなのに色が変わってしまう。
  • ラベルのない画像は事故のもと。
