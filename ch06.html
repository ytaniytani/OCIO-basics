第6章

OCIO の登場

ここまでで「困りごと」がそろいました。いよいよ、それを解決する道具が出てきます。

3分の映像を1本、まかされた

取引先のイベントで流す3分の映像を作ることになりました。締め切りは来週で、作り直す余裕はありません。素材は4つあります。

素材どこからもとの色空間
スマホの動画自分で撮ったsRGB(画面用に仕上がっている)
一眼のログ映像カメラマンが撮ったLog(眠い灰色に見える)
3DCG外注のCG会社から届いたリニア(光の量そのまま)
フリー素材ネットで拾った分からない

編集ソフトに全部読みこんで並べてみたら、めちゃくちゃでした。CGだけ真っ白、ログ映像だけ灰色、明るさもバラバラです。しかも、自分のパソコンとチームの別のパソコンで見え方がちがいます。

ここは動かして見る部分です

JavaScript を有効にすると、4つの素材を色の管理あり・なしで比べられます。管理をしないと素材ごとに見え方がバラバラで、編集ソフトを変えるとさらに変わります。管理をすると全部そろい、ソフトを変えても同じになります。

「どう読みこむか」を誰も決めていない

原因は、第2章と第5章で見たことの組み合わせです。

  • 素材ごとに、もとの色空間がちがう(第2章)。
  • 計算するには、全部を光の量にそろえないといけない(第5章)。
  • でも、どの素材にどの変換をかけるかを、誰も決めていない。

さらに悪いことに、編集ソフトごとに「たぶんこうだろう」という思いこみがあります。ソフトAとソフトBで思いこみがちがえば、見え方も変わります。

ここで OCIO が登場します

OCIO を1文で言うと

「どの色空間からどの色空間へ、どう変換するか」を1つのファイルにまとめて、全部のソフトに同じ答えを出させるしくみ。

OpenColorIO(オープンカラーアイオー、略して OCIO)は、映画やアニメの制作現場で広く使われている、色の翻訳係です。無料で誰でも使えます。Blender や DaVinci Resolve、Krita のような無料のソフトにも入っています。

OCIO の実体は、config.ocio というたった1つのファイルです。そこに変換のルールが全部書いてあります。チームの全員が同じファイルを使えば、全員の画面で同じ色になります。

OCIO がないと、何ができないのか

ここは大事なので、はっきり書いておきます。色の管理をしないと、次のことができません。

  1. 「正解の色」を決められない。 ソフトを移るたびに色が変わるので、どれが本当の色なのか分からなくなります。
  2. CGと実写をなじませられない。 別々のものさしの上にいるので、いくら調整しても合いません。
  3. HDR版を後から作れない。 ふつうの画面用に仕上げてしまうと、全工程をやり直すことになります。
  4. 数年後に同じ色を再現できない。 どう変換したかの記録がどこにもないからです。
  5. チームで話が通じない。 「私の画面ではこう見える」の言い合いになって、決着がつきません。

とくに重いのが3番目の「HDR版を後から作れない」です。納品後に「HDR 版もほしい」と言われても、締め切りが来週では全工程をやり直せません。逆に言えば、OCIO を使えばこの5つが全部できるようになります。

順番にも意味があります

色の流れには決まった順番があります。ブロックを正しい順にならべてみてください。まちがえると、その並べかたに応じた壊れかたをします。

ここは動かして見る部分です

JavaScript を有効にすると、パイプラインを組み立てるパズルができます。正解は「入力変換 → 作業空間で作業 → ルック(味付け) → 出力変換」の順です。

正解は次の順番です。

順番やることなぜその位置か
1入力変換素材が何なのかを決めないと、先の計算の意味が決まらない
2作業空間で作業全部が同じものさしの上にいるので、混ぜても壊れない
3ルック(味付け)出力先を変えても味付けが保たれる位置
4出力変換見る機械に合わせて仕上げる、いちばん最後の工程

3番の位置がなぜ大事なのかは、第9章でじっくり確かめます。

ルールを1つのファイルにまとめる

OCIO を使うと、さっきの案件はこうなります。

  • 素材ごとに「これは sRGB」「これは Log」「これはリニア」と指定する。
  • 全部を共通の作業空間に翻訳してから編集する。
  • 最後にまとめて画面用に仕上げる。
  • この指定を config.ocio に書いて、みんなで共有する。

次の章では、その config.ocio の中身を実際に開いて、自分で書きかえてみます。

この章のまとめ

  • 素材ごとに色空間がちがうので、そのまま並べても作品にならない。
  • OCIO は「どの色空間からどの色空間へ、どう変換するか」をまとめたしくみ。
  • 実体は config.ocio という1つのファイル。チームで共有する。
  • 順番は 入力変換 → 作業 → 味付け → 出力変換。
