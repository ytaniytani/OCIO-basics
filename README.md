# 色のきほん — OCIO と ACES をさわって学ぶ

映像やCGの知識がない中学生向けに、**OpenColorIO (OCIO)** と **ACES** をさわって学べる Web サイト。

「読んで覚える」ではなく、**色がズレる事故を自分で起こして、自分で直せるようになる**ことを目標にしています。全11章＋付録2ページ、インタラクティブ部品15個。

## 見かた

ビルドは要りません。適当な静的サーバで開けば動きます。

```
npx http-server -p 8811 -s .
# http://127.0.0.1:8811/ を開く
```

GitHub Pages で公開する場合は、リポジトリのルートをそのまま公開先にしてください。相対パスしか使っていません。

## 方針

- **ビルド不要の静的サイト。** HTML と CSS と JavaScript のみ。フレームワークも外部 CDN も使いません。
- **外部への通信ゼロ。** アクセス解析もクッキーもありません。保存するのは進捗だけで、`localStorage` に閉じています。
- **JavaScript を切っても本文が読めます。** 部品の場所には、何が体験できるかの説明が入ります。
- **実写素材を使いません。** 教材の画像はすべてプログラムで生成しています。
- **簡略実装には、その旨を画面に表示します。** ACES の出力変換とミニ OCIO エンジンは学習用の簡略版です。ごまかしません。
- **土台の数値は規格どおり。** 色空間の原色・白色点・変換行列・伝達関数は公表値をそのまま使い、テストで検算しています。

## GitHub Pages で公開する

公開先はここになります。

```
https://ytaniytani.github.io/OCIO-basics/
```

有効にする手順は2通りあります。**どちらか一方**でかまいません。

### やりかたA: ブランチから直接公開(いちばん簡単)

1. リポジトリの **Settings → Pages** を開く
2. Source を **Deploy from a branch** にする
3. Branch に `claude/ocio-aces-learning-spec-590n3u`、フォルダに **/ (root)** を選ぶ
4. Save を押す

数分で上の URL が見られるようになります。ビルドは走りません。ルートに `.nojekyll` を置いてあるので、Jekyll の処理も入りません。

### やりかたB: GitHub Actions で公開

1. リポジトリの **Settings → Pages** を開く
2. Source を **GitHub Actions** にする
3. 対象のブランチに push する(`.github/workflows/pages.yml` が走ります)

こちらは公開するファイルを絞りこみます。サイト本体と `docs/` だけを公開し、`tools/` は公開しません。生成したファイルが古くなっていないかも、公開前に確かめます。

もし `Branch is not allowed to deploy to github-pages` というエラーで止まったら、**Settings → Environments → github-pages → Deployment branches** に、そのブランチを足してください。`main` にマージすれば、この設定は要りません。

### サブディレクトリで動くことは確認ずみです

プロジェクトの Pages は `https://<ユーザー名>.github.io/<リポジトリ名>/` という形になります。このサイトは絶対パスを1つも使っていないので、そのまま動きます。公開されるファイルだけを取り出して、サブディレクトリ配信で全ページを検査ずみです。

## テストと検査

```
# ブラウザで開くだけのテスト(24件)
open http://127.0.0.1:8811/tests.html

# 全ページをブラウザで検査(部品の起動、横スクロール、
# JavaScript オフ時の可読性、外部通信ゼロ)
node tools/check-site.mjs
```

`tests.html` が確かめること:

- 伝達関数と色域の往復が元にもどるか
- 公表値との一致(sRGB 0.5 → linear 0.2140、Rec.709 の輝度係数、ACEScg→Rec.709 行列、ACEScct、PQ)
- 出力変換が単調でピーク輝度を超えないか
- CPU 実行と GPU (GLSL) 実行の結果が一致するか
- YAML パーサが、対応していない書きかたを正しい行番号で断るか
- 教材の設定ファイル5本が読めるか(壊してある1本は、意図した行でエラーになるか)

## 執筆のための道具

`tools/` はサイトの動作には不要です。共通部分を1か所で直すためのものです。

```
python3 tools/build_pages.py       # ヘッダ・目次・前後リンクを全ページに反映
python3 tools/build_glossary.py    # docs/GLOSSARY.md から用語集を生成
python3 tools/build_pages.py --check   # 古くなっていないか調べる
```

`build_pages.py` は、日本語の途中で改行すると半角スペースになってしまう問題も、行を詰めて防ぎます。
